# Configuration

Every tunable and every feature flag. Setup steps are in [running-locally.md](running-locally.md).

## Configuration

All tunable parameters are a `Settings` Pydantic model in [`src/config.py`](../src/config.py) with validators. Non-secret values are set in committed [`config.toml`](../config.toml); secrets come from `.env` / GitHub Secrets. Precedence: **env var → `.env` → `config.toml` → the code defaults below** (so any field can be overridden ad-hoc via an env var). The `Default` column is the in-code fallback when a field is absent everywhere; `config.toml` ships the actual production values.

| Field | Default | Description |
|---|---|---|
| `llm_provider` | `openai` | `openai` or `anthropic` (production `config.toml` sets `anthropic`). |
| `council_llm_provider` | `None` | Override LLM provider for the advisory council only (heterogeneous strategy: cheap model for 7-persona council, frontier for main analysis). `None` → reuses `llm_provider`. |
| `council_llm_model` | `None` | Override model name for the council adapter (e.g. `gpt-5-mini`, `claude-haiku-4-5`). `None` → provider default. |
| `council_personas_dir` | `data/council_personas` | Directory with one JSON file per council member (`{"name": str, "style": str}`). Validate with `uv run python -m src.tools.validate_personas`. |
| `volatility_threshold` | `0.02` | Threshold that triggers full analysis (2%) |
| `council_volatility_threshold` | `0.03` | Extra threshold for the advisory council (8 LLM calls: 7 personas + chairman). Below this Δ the council is skipped even if the main gate passed. `0.0` disables. |
| `symbols` | `[AAPL, MSFT, NVDA]` | Monitored tickers (CSV in env — override with the 22-symbol portfolio) |
| `alpha_vantage_api_keys` | `[]` | CSV of keys for rotation on rate-limit |
| `symbols_etf` | `[]` | CSV of tickers classified as ETFs (e.g. `VT,QUAL,IHI,VB`). ETFs skip fundamentals fetching (no meaningful per-share EPS/P/E) and always receive `ValuationVerdict.UNKNOWN`. |
| `risk_symbols` | `[]` | CSV of Risk Watch tickers (inverse / safe-haven / VIX / sovereign-proxy). When empty, the Risk Watch use case is not built. |
| `risk_symbol_types` | `{}` | `SYM:TYPE,SYM:TYPE,...` mapping each `risk_symbols` entry to a `MacroRiskInstrumentType` (`INVERSE_EQUITY` / `INVERSE_TREASURY` / `SAFE_HAVEN` / `VOLATILITY` / `SOVEREIGN_PROXY`). |
| `nbp_enabled` | `false` | When `true`, wires `NbpClient` (`MacroIndicatorsPort`) into Risk Watch — adds the EUR/PLN, USD/PLN 30-day stress block to the e-mail. |
| `crypto_symbols` | `[]` | CSV of crypto tickers (clean form: `BTC,ETH`). Routed via `RoutingMarketDataPort` to `CoinGeckoAdapter`. News goes through Alpha Vantage with the `CRYPTO:` prefix added by `AlphaVantageClient`. Fundamentals always skipped (no per-coin EPS/P/E). |
| `crypto_volatility_threshold` | `0.05` | Separate volatility gate for `AssetType.CRYPTO` — equity threshold (2%) would treat BTC's natural 3-5% daily move as a signal every cycle. 5% keeps the LLM/council budget under control. |
| `symbols_unsupported_price` | `[]` | CSV of tickers the current price adapter cannot fetch (Finnhub free → 403 on EU-listed `.DE` / `.L`). Pre-filtered in `main_agent.main()` — they show up as **ignored**, not **errors**, so the report's error count reflects actual issues. |
| `symbol_throttle_seconds` | `0.0` | Sleep between symbols in the main loop. Set `> 0` to spread LLM calls across the OpenAI **TPM window** (council on OpenAI; tier 1 = 30k tokens / min) — at 30+ symbols with the 7-persona council, bursting hits 429s. Recommended: `2.0`. |
| `symbol_concurrency` | `1` | Number of symbols processed in parallel in the Fast Loop via a bounded `ThreadPoolExecutor` (production `config.toml` sets `4`). Each analyzed symbol internally fans the council out to ~7 concurrent OpenAI calls, so the real fan-out is ~N×7 — keep it conservative and lower it if you hit rate limits (HTTP 429). `1` runs sequentially. **`symbol_throttle_seconds` and contagion (`contagion_enabled`) only apply in sequential mode** — enabling contagion forces sequential processing regardless of `symbol_concurrency`, because peer-context reasoning depends on processing order. |
| `council_llm_provider` / `council_llm_model` | `None` | Route the advisory council to a cheaper / faster LLM. With 7 personas × N symbols the council dominates token use — pinning it to a cheap model (`gpt-5-mini`) keeps council cost low while the main analysis runs on Claude Sonnet 4.6. |
| `reflection_min_age_hours` | `6` | Minimum age (hours) a prediction must reach before `reflect_node` scores it. `reflect_node` resolves the **oldest** due (unverified, past-cutoff) prediction each cycle, draining the backlog rather than only ever touching the latest. `0` opts out of the age floor (backtest/legacy). The default `6` guards against an overlapping manual run prematurely closing a fresh prediction against a near-identical price (which would pollute `accuracy_score` and inflate the report hit-rate). |
| `ml_model_path` | `data/models/price_predictor.ubj` | XGBoost weights file |
| `notifications_enabled` | `false` | Enables email delivery |
| `digest_from_email` | `onboarding@resend.dev` | Resend sandbox sender |

Plus internal constants in `report_builder.py` (`DIVERGENCE_PRICE_THRESHOLD = 0.02`, `AV_LLM_CONFLICT_THRESHOLD = 0.3`, `LOW_SIGNAL_NEWS_THRESHOLD = 3`, `HIGH_RELEVANCE_BAR = 0.8`) and `xgboost_local.py` (hyperparameters `max_depth=4, eta=0.1, subsample=0.8`).

## Feature flags

**Optional alpha-data sources** (category "Data"): seven extra signals — SEC EDGAR insider flow, AlphaVantage earnings calendar, Finnhub options/IV, Reddit social velocity, FRED yield-curve, Finnhub analyst consensus, and regime-tagged RAG (vector memory). Each is a port + adapter with a **Null fallback** and is **off by default** in `config.toml` (`insider_flow_enabled`, `earnings_calendar_enabled`, `options_flow_enabled`, `social_velocity_enabled`, `yield_curve_enabled`, `analyst_consensus_enabled`, `vector_memory_enabled`) — so they make **zero network calls** until you flip a flag (and supply its key where needed). Enabled per-symbol signals are aggregated into an "Alpha Signals" report section; `vector_memory_enabled` needs migration `017`.

The FRED yield curve is no longer render-only. When **both** `yield_curve_enabled` and `regime_aware_enabled` are on, an inverted 10Y-2Y spread is cast as one `ELEVATED` **vote** into `RegimeDetector`. It is a vote, not a veto: `RegimeDetector` needs two `ELEVATED` votes to declare `RISK_OFF`, so an inversion on its own only moves the regime to `NEUTRAL`. That is deliberate — inversions can persist for months, and a veto would pin the agent in risk-off for all of it. The net FinOps effect is a saving: `RISK_OFF` raises the volatility threshold, so fewer cycles ever reach the paid ports.

The earnings calendar works the same way. With `earnings_calendar_enabled = true`, the next quarterly report is fetched **before** the graph runs and its proximity raises the volatility threshold (`IMMINENT` ≤ 2 days → ×1.5, `NEAR` ≤ 7 days → ×1.15, otherwise ×1.0). A 12-hour prediction taken the day before earnings is a coin flip, so the agent tightens the gate instead of burning tokens on analysis the report will invalidate — cutting spend and cleaning up the hit rate at once. The earnings and regime multipliers **compound**, and both are guaranteed `>= 1.0`, so the gate can only ever tighten. The event is fetched once per symbol and injected into the alpha-signals enrichment, so the gate adds **zero** paid API calls. With the flag off, no earnings port is touched at all.

`calibrated_confidence_enabled` closes the calibration loop. The repo already computed a reliability curve and ECE but only *displayed* them: when the 80–90% confidence bucket historically hit 55%, the ranking still trusted the raw 85%. With the flag on, `strength = confidence x |delta|` is computed on the confidence **corrected by that bucket's historical hit rate**, shrunk toward the raw value when the sample is small (`weight = count / (count + 10)`). Calibration therefore reorders the "Najsilniejsze sygnaly" ranking rather than merely labelling it. It is render-only: nothing is persisted, and in particular the `confidence_calibration` column from migration `016` (an LLM judge's post-hoc score) is never overwritten. The flag is independent of `calibration_curve_enabled` on purpose — one draws the Track Record section, the other changes the ranking.

`messenger_digest_enabled` fixes a real, silent failure. `TelegramNotifier` and `SlackNotifier` used to receive the **full** plain-text report, which routinely exceeds Telegram's 4096-character limit: the API answers `400` and the push disappears. Worse, the per-subscriber fan-out branch skipped `notifier.send_report` entirely, so push never fired once anyone was subscribed. With the flag on, push channels leave the email `CompositeNotifier` and instead receive a 5-line digest (cycle headline counts plus a closed-prediction scorecard), hard-capped at 1500 characters and sent **once** per cycle over the full results, independent of the fan-out. Zero cost — the Telegram Bot API and Slack webhooks are free. With the flag off the legacy composite is preserved bit-for-bit.

`model_scorecard_enabled` (migration `019`) surfaces the repo's strongest honesty signal, which users never saw: the walk-forward gate that refuses to ship a model worse than the naive baseline. Each Slow Loop training run now records one row **per symbol** — training is per-symbol, so ~43 runs overwrite a single `.ubj` and a scorecard without a `symbol` column would be meaningless — and the report renders the aggregate: "accepted N, rejected M, skipped K", the candidate's RMSE against baseline, directional hit rate, fold count, and a `STALE` badge past 21 days. A run where every candidate was rejected renders as exactly that; it is deliberate, uncomfortable truth rather than a bug. The section always carries `METRIC_NOTE`, which states that the metrics describe the *candidate on walk-forward folds* while the shipped model is refit on all data — without it a trust section would itself be dishonest. Writes are best-effort: a missing migration cannot break training.

`cycle_diff_enabled` adds a "🔄 Zmiany nastawienia" section: the council flipping BUY→SELL on a symbol, a sentiment jump past 0.2, or a consensus drop past 0.25, all measured against the previous stored cycle. It needs no migration — the verdicts have been sitting in the `council_verdict` JSONB since `005`. Two guards make it trustworthy rather than dramatic. Comparisons older than 48 hours degrade to `STALE_COMPARISON` and render with the age spelled out ("porownanie z cyklu sprzed N dni") — the Fast Loop cron is commented out, so "yesterday" is often last week. And a symbol with no *fresh* verdict (filtered out by the volatility gate) is skipped entirely, so an old flip cannot resurface cycle after cycle. Zero cost: a Supabase read of data already paid for.

`receipts_enabled` (migration `020`) persists the evidence chain behind each prediction into a `decision_receipts` JSONB column: the RAG analogues actually used (now carrying their `id` and `similarity`, which the code used to discard), the SHAP-lite feature attributions, the **effective** volatility threshold after regime and earnings multipliers, and a `schema_version` from day one. Until now those artefacts were computed, rendered into one email and thrown away, so a prediction that turned out wrong could not be audited. The flag is a **precondition for graceful degradation, not a preference**: writing a new key before the migration exists returns `PGRST204` and kills the entire prediction write — the same gate `vector_memory_enabled` uses for its column. Zero cost — the data was already paid for this cycle. The MVP deliberately leaves provenance badges out (`AgentState` does not carry them; they would grow the receipt at `schema_version: 2`).

`shock_alerts_enabled` (migration `021`) adds a **fourth entry point**, [`main_watch.py`](../main_watch.py), on an hourly cron that runs **24/7 rather than only during NYSE hours** — BTC and ETH trade around the clock. It answers the one thing a once-daily digest cannot: an -8% move on BTC at 14:00 should not wait until tomorrow morning. Cost is **zero paid API calls** — free price sources (Finnhub / CoinGecko), a Supabase read, and free push channels; no LLM, no Alpha Vantage, no embeddings. Two hard contracts protect the rest of the system. The watch **never calls `save_price_snapshot`**: overwriting the snapshot hourly would make the Fast Loop measure its delta against an hour-old price instead of a cycle-old one, quietly shutting the volatility gate. And a **one-alert-per-symbol-per-day debounce** — enforced both by the domain predicate and by `UNIQUE(symbol, alert_date)` — keeps a chaotic market from training you to ignore the channel. A price snapshot older than 30 hours suppresses the alert entirely, because a stale reference point manufactures false alarms.

`options_flow_enabled` now does more than fill a table cell. With it on, the options port is fetched inside `_predict_node` — naturally **behind the volatility gate**, so a quiet cycle never pays for it — and the model's predicted move is compared against the move the options market implies (`implied_move_12h`, sqrt-time scaled). The report shows a **qualitative label** (`MODEL_AHEAD` / `MARKET_AHEAD` / `ALIGNED`), not a two-decimal sigma, and `edge_sigma` is persisted (migration `025`) so the hypothesis can be falsified later: does the `edge > 1.5σ` subset actually beat the rest? Two methodological caveats are stated in the module docstring rather than hidden: `implied_vol` is a chain-wide average, not the front-month at-the-money, and sqrt-time over calendar hours **overstates** the move across a weekend. The signal is informational and deliberately carries no decision-making role until validated on closed predictions. With the flag off, no options port exists and the cycle is byte-identical.

`alpha_fusion_enabled` (migration `022`) closes the repo's largest wasted investment. Five alpha sources were fetched, classified against domain thresholds, and then rendered **only into a table**: insiders could be buying by the million and neither the LLM prediction nor the seven XGBoost features would know. Fusion is a weighted sum of the *existing* domain classifications, renormalised over whichever sources are actually present, so a symbol with one available source is not silently penalised. The score reaches both the LLM prompt — **with its per-source breakdown**, so the composite stays auditable rather than becoming a black box — and `ml_feature_store` as an eighth feature. Enrichment had to move **before** the graph to make that possible; it previously ran after, which is precisely why the signals never reached anything. The paid-call count is unchanged: `enrich` already ran once per symbol, just later. In the view the column is `COALESCE(alpha_fusion_score, 0.0)` so `dropna` cannot cut the historical rows out of training (a train/serve skew the migration test freezes). Whether the hand-picked weights are signal or noise is decided by the walk-forward "beat the baseline" gate, not by intuition — which is why the flag is off by default.

`attestation_enabled` (migration `024`) makes the track record **cryptographically checkable**. At prediction time a SHA-256 commitment over the canonicalised prediction plus a random salt is written to `prediction_logs` and the **hash alone** is appended to a public JSONL file — until the salt is revealed the hash discloses nothing. Once the prediction settles, a **sweep** reveals every matured commitment (salt and plaintext), and `revealed_at` is stamped only *after* a successful publish, so a miss can never be marked-revealed-but-never-published. The sweep is deliberate rather than a reveal-on-settle hook: predictions for symbols later removed from `config.toml` would otherwise never be revealed, and to a sceptic that looks exactly like hiding losses. **Be honest about what this proves:** git commit dates are forgeable. The claim is *tamper-evidence under branch protection*, not an unforgeable timestamp. Canonicalisation is frozen by golden tests and carries a `schema_version` from the first commit, because a canonicalisation bug breaks verification of history with no way to repair it retroactively. Zero cost — local hashing, published in an existing workflow.

`portfolio_positions_enabled` (migration `023`) replaces a fiction. `stress_test` and `portfolio_pnl` computed on **equal weights**: someone holding 40% in NVDA received a VaR calculated as though they held 2.3% of each of 43 tickers. A `positions` table now feeds a `Portfolio` aggregate with real weights (renormalised over the symbols that actually have a current price), unrealised P/L per position, and cluster exposure — "your three largest positions are one correlation cluster, 61% of capital". Amounts are shown in PLN at the NBP rate, taken from `MacroRiskReport.polish_macro` as a **value**, never by injecting a port into the renderer. A **STALE badge is a requirement, not decoration**: the positions table is maintained by hand, and a stale portfolio produces a *false* P/L, which is worse than no section at all. A Supabase error degrades to no section rather than to wrong numbers. Phase 2 is now in: `suggest_band` knows the existing exposure. Suggesting a "full 4-5% position" to someone already holding 40% of their capital in that symbol was advice computed on an empty portfolio. Both `current_weight` and the symbol's **correlation-cluster** exposure can only ever *narrow* the band — three positions in one cluster are one position wearing three hats. Monotonicity is the contract: an empty portfolio is absence of information, never a buy signal, so exposure never upgrades a weak signal. Both arguments default to `None`, preserving the pre-phase-2 behaviour exactly.

`public_scorecard_enabled` publishes the one artefact that can earn a stranger's trust: a landing page carrying **aggregates only** — number of settled predictions, hit rate, ECE, and the reliability curve as a div-sparkline. `web_digest_enabled` could never do this: it publishes the *full private digest*, watchlist symbols and all. The scorecard leaks nothing — a hard anti-PII test asserts the absence of email addresses, amounts and ticker symbols from the rendered page, using input that deliberately contains "NVDA" and an address. It runs through a **second** `FileWebPublisher` instance on its own path; reusing the digest's instance would have one overwrite the other. Metrics are computed independently of `equity_curve_enabled` and `calibration_curve_enabled`, because those gate sections of a private email, not a public proof. The page carries a **methodology** section: an embarrassing hit rate during a weak stretch is the point, not a bug — verifiable humility beats promises. GitHub Pages deployment needs `pages: write` and `id-token: write`, now present in the workflow.

The report also **prints its own bill**. `_log_paid_call` already logged every paid external call; it now also increments a cycle-wide meter, and the digest carries a "koszt cyklu" section: how many paid calls fired, broken down by source, and an **estimated** dollar figure. The word *estimated* is load-bearing — the unit prices are an order-of-magnitude model, not an invoice, and the module says so. The most interesting case renders explicitly rather than self-suppressing: a cycle where the volatility gate filtered every symbol reports **zero paid calls**, which is the entire point of the FinOps architecture.

`weekly_recap_enabled` is the **only feature in the repo with a non-zero FinOps cost**, and the cost is exactly **one LLM call per week** — not per symbol, not per cycle, enforced by a test. The Slow Loop already ran every Sunday and sent the user nothing. It now composes a story: prediction of the week, miss of the week with the lesson `reflect_node` drew from it, the council's **vindicated dissenter** ("Soros was right while everyone said BUY"), and the week-over-week ECE delta. A hard sample-size rule lives in the domain: **below five closed predictions no recap is built and no email goes out**, because a thin week would otherwise manufacture drama out of noise. If the LLM call fails the deterministic recap is still sent, without the narrative. Insight text reaches the prompt through `fence_untrusted`, since `correction_insights` derives indirectly from news headlines.

**Repository variables:** none. All non-secret config lives in committed [`config.toml`](../config.toml), read directly by `Settings` — so there is nothing to map in the workflow `env:` and no `vars.*` drift to guard. The workflow injects only the secrets above; the split (secrets mapped, non-secret config kept out) is guarded by [`tests/test_workflow_env_wiring.py`](../tests/test_workflow_env_wiring.py).
